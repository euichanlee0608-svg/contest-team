# 공모전 팀모집 웹앱 — 설치 가이드

이 문서는 **오너(이 맥의 주인)가 브라우저·터미널에서 직접 해야 하는 일**의 체크리스트다.
코드는 이미 다 되어 있다(프론트·`gas/Code.gs`·공모전봇 `recruit_sync.py` + 배선). 남은 것은
구글 쪽 생성·배포와 깃허브 배포뿐이고, 그건 계정 인증이 필요해 사람만 할 수 있다.
전체 그림·계약은 `SPEC.md` 가 단일 출처다. 현황과 다음 단계(공개 모집 전 점검 목록 포함)는 `ROADMAP.md`.

## 준비물

- 구글 계정(오너 본인) — 시트·Apps Script 는 이 계정으로 만든다.
- 터미널 접근(랜덤 키 생성용).
- `~/contest_bot` 이 이미 떠 있어야 한다(공모전봇, 5번에서 설정을 넣는다).

## 체크리스트

### 0. 키 두 개 미리 만들어두기

터미널에서 아래 명령을 **두 번** 실행해 서로 다른 랜덤 문자열을 만든다.

```bash
openssl rand -hex 24
```

첫 번째 결과 = `PUBLIC_KEY`, 두 번째 결과 = `ADMIN_KEY`. 메모장 같은 데 잠깐 적어둔다(3번에서 씀).
**이 둘은 서로 다른 값이어야 한다** — 하나가 새도 다른 하나는 안전해야 하기 때문이다.

### 1. 구글 시트 만들기

1. [sheets.new](https://sheets.new) 로 새 스프레드시트를 연다.
2. 이름은 아무거나 상관없다. 다만 기존 **방문 통계용 시트와 헷갈리지 않게** 짓는다
   (예: "공모전 팀모집").
3. **파일 → 설정 → 시간대를 `(GMT+09:00) 서울` 로 바꾼다.** 이걸 빼면 마감일 셀이 하루 밀려
   아직 안 끝난 공고가 목록에서 사라질 수 있다.

탭과 헤더는 **손으로 만들지 않는다.** 3번에서 `setup()` 을 한 번 실행하면 `공모전`·`문항`·`지원`
탭과 헤더가 정확한 이름으로 자동 생성된다(탭 이름이 한 글자만 달라도 코드가 못 찾으므로 손으로
만드는 것보다 안전하다). 자동 생성된 뒤 **새 시트의 기본 탭 `시트1` 은 지운다.**

아래 표는 각 탭에 무엇이 들어가는지 보려고 적어둔 참고용이다.

**`공모전` 탭**

| A | B | C | D | E | F | G | H | I | J | K | L |
|---|---|---|---|---|---|---|---|---|---|---|---|
| contest_id | 제목 | 링크 | 마감표기 | 마감일 | 주최 | 지원자격 | 요약 | 출처 | 갱신시각 | 모집상태 | 팀소개 |

→ **K(모집상태)·L(팀소개)은 오너가 손으로 채우는 열**이다. 코드는 이 두 열을 절대 안 건드린다.
빈칸이면 모집상태는 "열림"으로, 팀소개는 기본 문구로 취급된다.

**`문항` 탭**

| A | B | C | D | E | F | G |
|---|---|---|---|---|---|---|
| qid | contest_id | 질문 | 도움말 | 순서 | 최대글자수 | 사용 |

→ `contest_id` 를 비우면 **모든 공모전에 공통으로 뜨는 질문**이 된다. 이 탭은 전부 오너가
직접 채우고 고치는 곳이다(개별 공모전 문항이 하나도 없어도 공통문항만으로 모집이 돈다).

**`지원` 탭**

| A | B | C | D | E | F | G | H | I~R |
|---|---|---|---|---|---|---|---|---|
| 제출시각 | applicant_id | contest_id | 공모전제목 | 이름 | 연락처 | 소속 | 문항ID들 | 답변1~답변10 |

→ **A~R 은 코드(GAS)가 채운다.**
S열부터는 오너가 직접 채점하는 자리다 — 원하는 라벨을 **직접 입력해서** 만들면 되고
(예: S=사고력, T=협업, U=메모, V=결과), 코드는 S열 이후를 절대 읽지도 쓰지도 않는다.
그래서 `setup()` 도 A~R 헤더까지만 깔아준다(이미 있는 탭이면 빈 헤더 칸만 채운다).

### 2. Apps Script에 코드 붙여넣기

1. 방금 만든 시트 메뉴에서 **확장 프로그램 → Apps Script**.
2. 기본으로 있는 `Code.gs` 내용을 전부 지우고, 이 프로젝트의
   **`~/webapps/contest_team/gas/Code.gs`** 를 통째로 붙여넣는다.
3. 저장(⌘S 또는 저장 아이콘).

### 3. 스크립트 속성에 키 두 개 등록

1. 왼쪽 톱니바퀴 아이콘(**프로젝트 설정**) 클릭.
2. 맨 아래 "스크립트 속성" → **속성 추가**를 두 번 눌러 아래처럼 채운다.

| 속성 | 값 |
|---|---|
| `PUBLIC_KEY` | 0번에서 만든 첫 번째 랜덤 문자열 |
| `ADMIN_KEY` | 0번에서 만든 두 번째 랜덤 문자열 |

3. 저장.

4. 저장한 뒤 **편집기 상단의 함수 선택에서 `setup` 을 고르고 실행**한다. 이게 탭 3개와
   헤더를 만들어 준다. "권한 필요" 팝업이 뜨면: 본인 계정 선택 → 하단의 "고급" 클릭 →
   "(안전하지 않음) ○○○(으)로 이동" 클릭 → 허용. 본인이 만든 스크립트라 뜨는 정상적인
   경고다.
5. 시트로 돌아가 탭 3개가 생겼는지 확인하고, 기본 탭 `시트1` 을 삭제한다.

⚠️ `setup()` 을 실행하지 않고 배포하면 요청할 때마다
`시트 탭 [지원] 이 없습니다 — setup() 을 한 번 실행하세요` 로 실패한다.

### 4. 웹 앱으로 배포하고 URL 받기

1. 우측 상단 **배포 → 새 배포**.
2. 유형 선택 톱니바퀴를 눌러 **웹 앱**을 고른다.
3. 설명은 아무거나 입력(예: "공모전 팀모집 v1").
4. **실행 계정: "나(본인 구글 계정)"** 를 고른다. — 스크립트가 오너 권한으로 시트에 접근해야 하기 때문.
5. **액세스 권한: "모든 사용자"** 를 고른다. — "Google 계정이 있는 사용자"를 고르면 안 된다.
   지원자·정적 프론트는 구글 로그인 없이 이 주소를 호출하므로 반드시 "모든 사용자"여야 열린다.
   (방문 비콘 GAS 가 로그인 없이 동작하는 것으로 미루어 그쪽도 같은 조합일 것이다.)
6. **배포** 클릭. 권한 승인 팝업이 뜨면 3번 마지막에 적은 절차와 같은 방식으로 통과시킨다.
7. 배포가 끝나면 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/.../exec` 형태)을
   그대로 복사해 어딘가에 저장해둔다 — 이게 5번에서 두 군데에 넣을 GAS 주소다.

⚠️ **나중에 코드를 고칠 때는 "새 배포"를 다시 만들지 말 것.** 배포 → 배포 관리 → 연필 아이콘 →
새 버전으로 저장, 이 순서를 쓴다. 새 배포를 만들면 URL 이 바뀌어서 프론트·공모전봇 설정을
전부 다시 고쳐야 한다.

### 5. 키와 URL을 각자 자리에 넣기

**프론트(공개되는 쪽)** — `js/config.js` 를 열어 맨 위 두 줄을 채운다. 이 파일이 설정의 유일한
자리이고, `js/api.js` 는 그 값을 읽기만 하므로 건드리지 않는다.

```js
window.CONTEST_TEAM_CONFIG = {
  GAS_URL: "https://script.google.com/macros/s/.../exec",   // 4번에서 받은 주소
  PUBLIC_KEY: "0번의 첫 번째 랜덤 문자열",
  ...
```

두 값이 비어 있으면 화면은 표본 데이터로만 돌고 제출은 막힌다(그 상태를 화면에도 알려준다).

**공모전봇(`~/contest_bot/.env`)** — 아래 두 줄을 추가한다.

```
RECRUIT_GAS_URL=<4번에서 받은 웹 앱 URL — 프론트와 같은 값>
RECRUIT_ADMIN_KEY=<0번에서 만든 두 번째 랜덤 문자열 — ADMIN_KEY>
```

넣은 뒤 봇을 재시작해야 반영된다.

```bash
launchctl unload ~/Library/LaunchAgents/com.leechan.contestbot.plist
launchctl load   ~/Library/LaunchAgents/com.leechan.contestbot.plist
```

⚠️ **`ADMIN_KEY` 는 절대로 프론트 코드나 깃에 넣지 않는다.** 이 키를 알면 지원자의 이름·연락처를
읽어갈 수 있고(`t=inbox`) 공모전 목록도 마음대로 바꿔치기할 수 있다(`t=sync`) — 웹페이지 소스 보기는
누구나 할 수 있으므로 프론트에 들어가는 순간 공개된 것과 같다.

### 6. 동작 확인

브라우저 주소창에 아래 형태로 직접 열어본다.

```
<GAS 웹 앱 URL>?t=feed&key=<PUBLIC_KEY>
```

`{"ok":true, ...}` 형태의 JSON 이 보이면 여기까지는 성공이다.

### 7. 프론트를 깃허브 페이지로 올리기

```bash
cd ~/webapps/contest_team
git init && git add -A && git commit -m "첫 배포"
gh repo create contest-team --public --source=. --push
```

그다음 깃허브에서 **Settings → Pages → Source 를 `main` / `root`** 로 켠다.
몇 분 뒤 `https://<아이디>.github.io/contest-team/` 이 열린다. 이 주소가 지인에게 보낼 링크다.
`.nojekyll` 은 이미 들어 있다(없으면 Pages 가 `js/` 폴더를 무시한다).

### 8. 끝까지 한 번 통과시켜 보기

페이지를 열어 공모전 카드가 뜨는지 보고, **직접 지원서를 한 건 제출해 본다.**
시트 `지원` 탭에 행이 쌓이고 텔레그램으로 "새 지원 도착" 알림이 오면 전 구간이 연결된 것이다.
(테스트로 넣은 행은 시트에서 지우면 된다.)

## 평소 쓰는 법

- 텔레그램 공모전봇 카드에서 **🔖 (관심있음)** 을 누르면, 그 공고가 자동으로 웹앱에 뜬다
  (누르는 즉시 + 아침/오후 브리핑 때 한 번 더 전체 동기화).
- 지원자는 **공통 항목 4개**(역할·목표 수준·강점·시간과 회의)를 고른다. 지원 탭 I~L 에 한 칸씩 쌓인다.
  공통 항목 문구는 `js/apply.js` 의 `PROFILE` 에서 고친다.
- 공모전봇은 관심 등록 중 **팀 공모전만** 올린다(교환학생·과목 안내·장학금 제외). 관심을 해제해도 시트 행은
  남으니, 모집을 내리려면 K열에 `닫힘` 을 적는다.
- **문항을 추가·수정**하려면 시트 `문항` 탭을 직접 고친다. 처음 `setup()` 때 기본 질문 3개가 들어간다.
  ⚠️ 답변 칸이 10개라 **활성 문항은 공모전당 6개까지**(넘으면 지원 화면이 멈춘다). 공통문항은 `contest_id` 를 비워두고,
  특정 공모전 전용 문항은 그 공모전의 `contest_id` 를 채운다. `순서` 열 숫자로 노출 순서가 정해진다.
- **모집을 닫거나 팀 소개를 바꾸려면** 시트 `공모전` 탭의 K열(모집상태)·L열(팀소개)을 직접 고친다.
- **지원자 답변 확인·채점**은 시트 `지원` 탭에서 한다. 왼쪽(A~M)은 지원자가 낸 내용, N열부터
  오른쪽이 오너가 직접 적는 채점란이다.
- 새 지원이 들어오면 공모전봇이 **5분 안에** 텔레그램으로 지원 1건당 메시지 1개(이름·연락처·공통 항목·
  질문과 답 전체)를 보낸다. 채점은 시트에서 한다.

## 공개판 배포 (모르는 사람용, Cloudflare Pages)

```bash
npx wrangler login              # 최초 1회(브라우저 로그인)
bash tools/deploy_public.sh     # JS 검사 → 공개판 빌드(신원 흔적 게이트) → 비콘 검사 → recruit-lab 배포
```
지인용(GitHub Pages)은 `git push` 로 따로 나간다. 운영자 이력 문구는 `public/operator.html`.

막혔을 때 (2026-09-15 실측):
- `Your user email must been verified [code: 8000077]` → Cloudflare 계정 **이메일 인증**을 안 한 것. 대시보드에서 인증 메일의 버튼을 누르면 풀린다.
- `wrangler pages project create` 가 Workers 로 넘기려다 실패 → 스크립트가 **프로젝트 최초 생성 때만** `--force` 를 붙인다. 이후 deploy 에는 붙이지 않는다.
- 배포 주소는 `recruit-lab.pages.dev`(Pages). Workers 주소(`*.workers.dev`)는 계정 이름이 드러나서 일부러 피했다.
- 사이트 응답 확인은 `curl`/`urllib` 기본 UA 가 403 이므로 브라우저 UA 를 줘야 한다.

### 공모전 제안 기능 (공개판) — 오너가 할 일
1. `gas/Code.gs` 를 Apps Script 에 **다시 붙여넣고** 새 버전으로 배포한다(웹 앱 URL 은 그대로).
2. 편집기에서 `setup()` 을 **한 번** 실행 → 시트에 '제안' 탭이 생기고, 이미 있으면 I~S 헤더(문항ID들·답변1..10)가 채워진다.
3. 공모전봇을 재기동하면 5분마다 새 제안이 텔레그램 카드로 온다(관심목록 등록 / 핏 안 맞음·시간 부족 거절 메일 **초안** / 무시).
   거절 메일은 Gmail **임시보관함에 초안만** 저장된다 — 발송은 직접 한다.
4. 폭주하면 COT봇 `/webapp_kill` 에서 `공모전 제안(공개판)` 을 끈다.

## 검증 게이트 (배포 전 필수)

프론트/GAS 를 고쳤으면:

```bash
# node --check 는 인자를 여러 개 줘도 첫 파일만 본다. 반드시 하나씩 돌린다.
for f in js/*.js; do node --check "$f" || break; done
# 헤드리스 크롬으로 데스크톱 + 390px(모바일) 두 뷰포트 확인
#   ⚠️ 이 맥의 크롬은 --window-size 를 500px 미만으로 못 내린다. 390px 실측은
#      390px 짜리 iframe 에 넣어 찍어야 진짜 모바일 레이아웃이 보인다.
node ~/webstats/check_beacon.js
# 감사기는 websocket-client 가 필요하다(시스템 파이썬에 깔지 않는다 — 전역지침 10.5)
python3 -m venv /tmp/auditvenv && /tmp/auditvenv/bin/pip -q install websocket-client
/tmp/auditvenv/bin/python ~/repo_tools/webapp_audit/audit_webapps.py \
  ~/webapps/contest_team/index.html ~/webapps/contest_team/apply.html
```

공모전봇 쪽(`recruit_sync.py` 등)을 고쳤으면:

```bash
cd ~/contest_bot && ~/contest_venv/bin/python -m pytest tests/ -q
```

무엇 하나라도 빨간불이면 배포하지 않는다.
